# Підключення MCP-сервера

## Бік 1 — агент кодування
- **Який агент і версія**: OpenCode 1.18.32 (а також Claude Code CLI через конфігурацію `.mcp.json`)
- **Чому саме він (шлях за $0 чи наявна підписка)**: OpenCode є повністю відкритим та безкоштовним інструментом (шлях за $0), підтримує стандартні конфігурації MCP та локальні моделі (Ollama), не вимагаючи платної підписки.
- **Де лежить конфігурація**: `opencode.json` (та `.mcp.json` для Claude Code) у корені репозиторію.
- **Конфігурація дослівно (значення секретів вирізано, лишилися посилання на змінні)**:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "lab2-corpus": {
      "type": "local",
      "command": ["npx", "tsx", "src/mcp/server.ts"],
      "enabled": true,
      "environment": {
        "MCP_CLIENT_LABEL": "opencode"
      },
      "timeout": 5000
    }
  }
}
```
А також `.mcp.json` для Claude Code:
```json
{
  "mcpServers": {
    "lab2-corpus": {
      "type": "stdio",
      "command": "npx",
      "args": ["tsx", "src/mcp/server.ts"],
      "env": {
        "MCP_CLIENT_LABEL": "claude-code",
        "OLLAMA_URL": "${OLLAMA_URL:-http://localhost:11434}"
      }
    }
  }
}
```
- **Що викликано**: інструменти `search_corpus` (query: "Model Context Protocol architecture") та `fetch_chunk` (id: "doc-01#0000").
- **Доказ**: рядки `source=opencode` у `docs/lab2/traces/mcp-calls.jsonl`.

## Бік 2 — застосунок
- **Де код клієнта**: `scripts/mcp-demo.ts`
- **Команда запуску**: `npx tsx scripts/mcp-demo.ts "Model Context Protocol"`
- **Що викликано**: обидва інструменти (`search_corpus`, `fetch_chunk`) + один виклик за межею (`id: "doc-99#0000"`), щоб показати відмову (`Refusal`).
- **Доказ**: рядки `source=lab2-app` у `docs/lab2/traces/mcp-calls.jsonl`, вивід команди збережено у `docs/lab2/traces/mcp-demo-output.txt`.

## Що зламалося з першого разу
| Що саме | На якому боці | Причина | Що змінив у сервері чи конфігурації |
|---|---|---|---|
| Помилка `spawn EINVAL` або `spawn npx ENOENT` на Windows | Клієнт застосунку (`scripts/mcp-demo.ts`) | На платформі Windows системний процес не знаходить `npx` без розширення `.cmd` при прямому запуску через child_process | Додано вибір команди `process.platform === 'win32' ? 'npx.cmd' : 'npx'` у транспорт `StdioClientTransport` |
| Попередження `NativeCommandError` через stderr | Запуск підпроцесу сервера в PowerShell | PowerShell перехоплює будь-який рядок у `stderr` як виняток середовища, тоді як stdio MCP-сервер використовує `stderr` для діагностики | Налаштовано перехоплення stderr (`stderr: 'pipe'`), а JSON-RPC протокол ізольовано в stdout |
| Невідповідність ембедера при завантаженні індексу | Сервер (`src/mcp/server.ts`) | Якщо в коді жорстко зафіксовано `ollamaEmbedder()`, а `data/index.json` зібрано іншим провайдером, `loadIndex` викидає помилку перевірки | Додано автовизначення ембедера за назвою в заголовку індексу (`fake:`, `google:`, `ollama`), що дозволяє серверу стабільно працювати офлайн |

## Чим відрізняються два боки
- **Робоча тека і оточення процесу**: Агент кодування запускає сервер зі своєї власної робочої теки (тому в `src/mcp/server.ts` шляхи обчислюються строго від `import.meta.url`, а не `process.cwd()`). Клієнт застосунку передає очищене середовище через `getDefaultEnvironment()` з додаванням маркеру `MCP_CLIENT_LABEL=lab2-app`, запобігаючи витоку сторонніх змінних оточення.
- **Таймаути клієнта проти таймауту сервера**: У клієнтів агента таймаути можуть сягати 60 с (Codex) або 600 с (Gemini). Власний таймаут сервера у `src/mcp/tools.ts` зафіксовано на рівні 10 000 мс (`withTimeout`), що запобігає «мовчазному зависанню».
- **Що з цього я зафіксував у mcp-spec.md як вимогу, а не як випадковість**: Таймаут обробника 10 с, валідація через білий список `id` в індексі, ізоляція шляхів через `import.meta.url`, обрізка фрагментів до `LIMITS.chunkChars`.

## Секрети
- **Жодного значення ключа в закомічених конфігураціях**: Перевірено відсутність API-ключів у `.mcp.json` та `opencode.json` (використовуються змінні `${OLLAMA_URL:-http://localhost:11434}` або безпечні локальні налаштування).
- **Де насправді лежать ключі**: Справжні ключі зберігаються у `.env` (який додано до `.gitignore` і санітизується верифікатором брами злиття), а для демонстрації та CI сервер працює повністю локально без мережевих ключів.
