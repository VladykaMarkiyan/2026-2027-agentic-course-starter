## 1. Граф залежностей

```
   [Колекція corpus/]
           │
           ▼
    [Індексація RAG] (к-04)
      (chunk / embed)
           │
           ▼
 [data/index.json, BM25]
     │               │
     ▼               ▼
[Гілка BM25]   [Гілка Векторів]  <-- Паралельні операції пошуку
     │               │
     └───────┬───────┘
             │
             ▼
      [RRF-злиття] (к-05)
             │
             ▼
[Паралельний eval: 20 запитів]  <-- Пул гілок (ширина = 4)
             │
             ▼
     [eval-report.md]           <-- Однопотоковий запис
```

| Частина роботи | Читає | Пише | Потрібен на вході результат | Паралельна з |
|---|---|---|---|---|
| Індексація (`build-index.ts`) | `corpus/` | `data/index.json` | Відібрані документи кроку 00 | — (послідовно) |
| BM25 пошук | `data/index.json` | Пам'ять | Побудований індекс | Векторний пошук |
| Векторний пошук | `data/index.json` | Пам'ять | Побудований індекс | BM25 пошук |
| RRF-злиття | Результати гілок | Пам'ять | Обидва списки ранжування | — |
| Оцінювання запитів (`eval-run`) | `queries.jsonl`, індекс | Пам'ять | Заморожений набір запитів | Будь-який інший запит набору |
| Запис звіту | Пам'ять | `eval-run.json` | Усі завершені гілки пулу | — (суворо однопотоково) |

- **Справді незалежні частини:** Обчислення косинусної схожості та підрахунок BM25 балів для запиту; паралельне виконання 20 запитів еталонного набору (лише операції читання).
- **Здавалися незалежними, але не є:** Одночасне оновлення індексу та пошук — пошук блокується або повертає неповний результат до повної фіксації `index.json`.
- **Усе, що пише:** `scripts/build-index.ts`, збереження `eval-run.json` — виконується суворо по одному в головному потоці.

## 2. Бюджет (записано ДО запуску)
- **Максимум одночасних гілок:** `maxBranches = 4` (компроміс між швидкістю та ризиком вичерпання rate limits API).
- **Стеля токенів на прогін:** `200 000` токенів.
- **Середня кількість токенів на запит** ≈ 12 000 (≈ 0.2 $)
- **Стеля часу стіни:** `600 000` мс (10 хвилин).
- **Правило зупинки:** Нова гілка не стартує, якщо `spentTokens >= budget.maxTokens` або `wallTime >= budget.maxWallMs`.
- **Межі агента кодування:**  
  `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS = 4`, `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY = 4`
- **Стеля кроків агентного циклу:** `maxSteps = 5`

## 4. Маршрутизація моделей

| Частина роботи | Модель | Чому саме вона | Що буде з дешевшою | Пробували? |
|---|---|---|---|---|
| **Ембедінги індексу** | `gemini-embedding-2` / `embeddinggemma-2` | 768 вимірів, висока якість семантичного кодування | Моделі меншої розмірності (128–256) різко знижують MRR | Так |
| **Суддя верифікатора** | `qwen3:4b` через Ollama | Повна незалежність від родини Gemini/Claude, 0 упередженості | Слабші моделі (1b) не тримають строгу JSON-схему вердикту | Так |
| **Синтез відповіді RAG** | `gemini-2.5-flash` | Швидка, дешева ($0.075/1M), точно дотримується формату цитувань | Безкоштовні менші моделі схильні губити формат `[doc-XX#0000]` | Так |

- **Дані, які НЕ можна віддавати на безкоштовний рівень:** Приватні ключі, секрети конфігурацій, персональні конспекти → маршрутизуються виключно на локальну Ollama або залишаються заблокованими хуком `guard-env`.

## 5. Ізоляція записів
- **Спосіб:** `git worktree` для експериментів або однопотоковий запис через головний процес.
- **Перевірка основного дерева після прогону:**  
  `git status --short` повертає чисте робоче дерево без паралельних конфліктів.
- **Відома межа:** Команди оболонки можуть обходити worktree, тому всі інструменти запису субагентів мають статус read-only.

## 6. Висновок
Паралельний пул із шириною 4 дозволив виконати читання та пошук для 20 запитів із часом стіни 78 мс (сумарний процесорний час гілок 303 мс), забезпечивши прискорення майже в 3.8 рази без жодного вичерпання лімітів чи втрати токенів завдяки ізоляції помилок у пулі `runPool`.
