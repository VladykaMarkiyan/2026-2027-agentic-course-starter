## 1. Задача й користувач

**Хто користувач:** Розробник агентних систем та інженер програмного забезпечення, який інтегрує інструменти через Model Context Protocol (MCP) та розгортає агентні цикли на базі AI SDK 7 і OpenTelemetry.

**Яке питання він ставить і що робить із відповіддю:**  
Користувач запитує про точні формати повідомлень MCP (JSON-RPC 2.0, ініціалізація, схема виклику інструментів, коди помилок), особливості реалізації гібридного пошуку (RRF-злиття, параметри BM25, векторна схожість) та конфігурацію трасування. Отриману відповідь розробник безпосередньо використовує для написання коду, конфігурації `.mcp.json` або усунення збоїв взаємодії агентів.

**Що він робить сьогодні без асистента:**  
Вручну шукає у розрізнених специфікаціях, документаціях бібліотек на GitHub та наукових статтях; це займає багато часу, а при переході між версіями протоколів часто виникають тонкі помилки несумісності, які складно діагностувати.

## 3. Вимірювані цілі v1

Кожна ціль — це чітке число, спосіб його вимірювання та файл у `docs/lab2/`, де воно буде зафіксоване.

| # | Ціль | Число | Як міряється | Де число |
|---|---|---|---|---|
| **G1** | Точність відповідей на еталонному наборі | $\ge 75\%$ правильних відповідей | Прогін усіх $\ge 20$ запитів з `docs/lab2/golden/queries.jsonl` за критеріями оцінювання | `docs/lab2/eval-report.md` |
| **G2** | Частка відповідей із валідним цитуванням | $\ge 80\%$ відповідей | Відповідь містить щонайменше один коректний ідентифікатор документа (`doc-XX`), що збігається з `must_cite` | `docs/lab2/eval-report.md` |
| **G3** | Точність обробки відмов (`unanswerable`) | $100\%$ ($K$ із $K$ запитів) | Запити з тегом `unanswerable` отримують явну відмову з вказівкою на відсутність інформації, а не вигадану відповідь | `docs/lab2/eval-report.md` |
| **G4** | Затримка відповіді гібридного пошуку | медіана $p_{50} \le 1.5$ с (без урахування генерації тексту LLM) | Автоматичний вимір затримки пошуку (BM25 + вектор + RRF) у тестовому скрипті | `docs/lab2/eval-report.md` |

## 4. Non-goals v1 (чого асистент НЕ робить)

1. **Не є універсальним чат-ботом для довільних тем:** Якщо питання виходить за межі 15 документів колекції, асистент зобов'язаний відмовити (`unanswerable`), а не вигадувати відповідь із загальних знань моделі.
2. **Не виконує небезпечних команд або мутацій файлової системи:** v1 асистента та його MCP-сервер надають виключно операції читання (`read-only`: пошук та витяг фрагментів документів).
3. **Не підтримує індексацію зовнішнього веб-контенту «на льоту»:** Індекс формується локально детермінованим скриптом перед запуском.
4. **Не використовує платних хмарних векторних баз даних:** Усі індекси (BM25 і векторні ембедінги) зберігаються локально в репозиторії або пам'яті процесу без зовнішніх платних залежностей.
5. **Не підтримує багатокористувацьку автентифікацію чи сесії:** v1 розрахований на локальну роботу розробника або роботу через стандартний MCP-клієнт.

## 5. Обсяг v1

**Входить до v1:**
- Колекція з 15 документів у форматі Markdown (`data/docs/doc-01.md` ... `doc-15.md`).
- Еталонний набір запитів `docs/lab2/golden/queries.jsonl` ($\ge 20$ запитів із валідатором).
- Модуль детермінованої фрагментації тексту `src/rag/chunk.ts`.
- Модуль обчислення ембедінгів `src/rag/embed.ts` (Ollama qwen / Gemini / офлайн fake для тестів).
- Модуль лексичного пошуку BM25 та векторного косинусного пошуку.
- Алгоритм злиття рангів Reciprocal Rank Fusion (RRF, $k=60$) у `src/rag/hybrid.ts`.
- Механізм цитування джерел із зазначенням `id` документа та фрагмента.
- Власний MCP-сервер (`src/mcp/server.ts`) з інструментами `search_corpus` та `fetch_chunk`.
- Конфігурація підключення MCP-сервера до агентів кодування (`.mcp.json`).
- Модульні та інтеграційні тести без зовнішньої мережі (`npm test`).

**Не входить до v1 (передбачено для наступних версій):**
- Автоматичне оновлення індексу при зміні файлів (file watcher).
- Графічний користувацький веб-інтерфейс (чат-UI).
- Підтримка документів у форматі PDF, DOCX чи аудіо.

## 6. Критерії приймання

| # | Критерій (перевірне твердження) | Чим перевіряється |
|---|---|---|
| **A1** | Повний набір тестів `npm test` зелений, включно з тестами без мережі для фрагментації, пошуку та MCP | Команда `npm.cmd test` завершується з кодом 0 (100% тестів проходять) |
| **A2** | Еталонний набір містить $\ge 20$ запитів, задовольняє схему Zod та містить $\ge 3$ запити `unanswerable` | `npx tsx scripts/validate-golden.ts` успішно валідує `docs/lab2/golden/queries.jsonl` |
| **A3** | Модуль гібридного пошуку повертає RRF-ранжовані фрагменти з точним цитуванням джерел | Тести `tests/rag.test.ts` проходять локально без виклику зовнішніх мереж |
| **A4** | MCP-сервер коректно обробляє виклики `search_corpus` та `fetch_chunk`, валідує схеми та відхиляє некоректні параметри | Інтеграційний тест `tests/mcp.test.ts` перевіряє обидва інструменти та обробку помилок |
| **A5** | Усі звіти (`baseline.md`, `indexing.md`, `retrieval.md`, `eval-report.md`, `budget.md`, `mcp-spec.md`, `mcp-integration.md`, `README.md`) містять конкретні числа та відтворювані результати | Наявність файлів у `docs/lab2/` та перевірка відсутності пропущених placeholder-значень |

## 7. Обмеження

- **Бюджет:** $0 витрат завдяки використанню локальних ембедінгів Ollama / безкоштовного рівня Gemini API для оцінки, а також фейкових провайдерів для швидких детермінованих тестів у CI.
- **Мережа в CI:** Усі модульні та регресійні тести виконуються офлайн без залежності від зовнішніх серверів чи API-ключів.
- **Апаратні вимоги:** Робота на стандартній машині розробника під керуванням Windows / Linux / macOS (підтримка локальної моделі Ollama або виклик Gemini Flash).
- **Часові рамки:** Виконання занять 05–08 курсу відповідно до графіку лабораторної роботи.
